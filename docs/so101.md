# SO-101 contract and action-encoding foundations

The SO-101 follower has five arm joints and an independent gripper. This patch
extracts the contract and action-encoding layer from an experimental SO-101
simulation integration, so that the remaining adapter can be reviewed separately.
It supplies no physical-robot connection or registered `--benchmark so101` runtime.

## Joint dimensions

Use `embodiment="so101"` when constructing SO-101 `RobotState`, `ArmCommand`,
`Trajectory`, and `RobotPlanningContext` values. The arm target contains five
angles in radians. The gripper remains a separate normalized value; adding it to
the arm vector would give the wrong contract shape.

Existing embodiments retain their declared joint counts: YAM has six, and the
Panda and R1 profiles have seven per arm. Omitting `embodiment` still selects
`robosuite`. Supplying an SO-101 vector with that default is rejected.

`CapApi(..., home_joint_positions=...)` now requires a finite vector with the
declared robot's joint count, for each supplied arm. Previously, any six- or
seven-element vector was accepted, even for a robot of the other dimension;
five-element homes were always rejected. Invalid configurations now fail during
API construction. Existing callers must provide a home matching their adapter's
declared embodiment.

## Absolute-position action encoding

`cap_harness.so101.codec.SO101ActionCodec` is a host-side building block for an
adapter. It converts one `primary` arm command into six actuator targets:

1. The five commanded arm angles, checked against supplied actuator bounds.
2. The gripper angle interpolated between its supplied bounds, with `0` closed
   and `1` open.

An explicit gripper command overrides the cached target. If omitted, the cached
target takes precedence over the measured opening, so a jaw stalled on an object
keeps its intended target through the next arm command. Without a cached target,
the measured opening is used. The codec rejects other embodiments, other arm
names, malformed actuator bounds, out-of-range arm targets, and invalid normalized
gripper targets. It encodes targets without sending them to any controller.

Actuator limits must come from the selected robot model or calibration. This
normalized interpolation is a simulation convention, not a calibrated conversion
to the physical LeRobot motor interface.

## Validation

The new tests exercise the contract boundaries and a fake adapter through
`set_gripper`, `move_to_joints`, and `go_home` for five-, six-, and seven-joint
robots. They verify that motion preserves the commanded gripper target and that
an explicit home is copied rather than aliased to the caller's array. Codec tests
cover gripper endpoints, intermediate openings, cached targets, and invalid
inputs. All of these checks run with the base and development dependencies.

```bash
python -m pytest tests/test_so101_contracts.py tests/test_contracts.py tests/test_api.py -q
```

These unit tests validate software contracts and encoding. Simulation model
import, perception, planning, harvest-task evaluation, and physical-robot
validation belong in subsequent contributions with their own reproducible checks.
